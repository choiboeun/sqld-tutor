## 발견 및 수정된 버그

### Bug 1 — 범위 밖 숫자 입력 시 chatbot 오작동 (수정 완료)

**증상:** pending 문제가 있을 때 "7" 입력 → chatbot이 응답 → 다음 "1" 입력도 chatbot → LLM 환각 발생  
**원인:** intent_classifier가 "7"을 유효 답변으로 인식하지 못해 chatbot으로 라우팅. 이후 `current_mode`가 "chat"으로 변경되어 "1"도 chatbot으로 감  
**수정:** `_ANY_NUMBER = re.compile(r"^\d")` 추가. pending 중 숫자 입력은 항상 drill/review 유지

### Bug 2 — explain 반복 실행 (수정 완료)

**증상:** 같은 카테고리 오답 연속 시 매번 동일한 개념 설명 반복 출력  
**원인:** adaptive_difficulty_router가 매 오답 후 `정답률 < 20%` 조건을 재평가하여 계속 explain 유도  
**수정:** `last_explained_category` 필드 도입. 설명한 카테고리는 정답 전까지 재실행 방지

### Bug 3 — "이해했어" → explain_node 오작동 (수정 완료)

**증상:** "이해했어" 입력 시 "이해했어는 SQLD 개념이 아닙니다" 응답  
**원인:** `_EXPLAIN = re.compile(r"...|이해")` — "이해"가 너무 광범위하게 매칭  
**수정:** `이해` → `이해[가하]`로 변경 ("이해가 안돼", "이해하고 싶어"는 매칭, "이해했어"는 제외)

### Bug 4 — intent_classifier "다음" 키워드 과잉 매칭 (수정 완료)

**증상:** "다음 개념 설명해줘" → explain이 아닌 drill 모드로 라우팅  
**원인:** `_DRILL = re.compile(r"문제|다음|풀어|시작")` — "다음"이 너무 광범위  
**수정:** `r"문제\s*(줘|내줘|풀게|풀어|주세요)?|풀어|시작"` ("다음" 제거)

### Bug 5 — pending 중 SQL 키워드 오발동 (수정 완료)

**증상:** 조인 문제를 풀면서 "SELECT 실행하면?" 입력 시 sql_node로 라우팅  
**원인:** `_SQL` 패턴이 pending 여부와 무관하게 항상 최우선 적용  
**수정:** `if not pending and _SQL.search(text):` — pending 없을 때만 SQL 모드 진입
