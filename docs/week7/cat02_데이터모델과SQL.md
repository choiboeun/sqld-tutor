## 1. 정규화(Normalization)

### 정규화 개념
- 데이터 중복을 최소화하고 데이터 무결성을 유지하기 위해 테이블을 분리하는 과정
- 함수적 종속성을 기반으로 함

### 함수적 종속성
- 속성 A의 값을 알면 속성 B의 값이 유일하게 결정될 때, B는 A에 함수적으로 종속
- **부분 함수 종속**: 복합 PK의 일부에만 종속 (2NF 위반)
- **이행 함수 종속**: A → B, B → C 이면 A → C (3NF 위반)

### 정규화 종류

| 단계 | 이름 | 조건 |
|------|------|------|
| 1NF | 제1정규형 | 모든 속성이 원자값(더 이상 분리 불가) |
| 2NF | 제2정규형 | 1NF + 부분 함수 종속 제거 |
| 3NF | 제3정규형 | 2NF + 이행 함수 종속 제거 |
| BCNF | 보이스-코드 정규형 | 3NF + 모든 결정자가 후보키 |
| 4NF | 제4정규형 | BCNF + 다치 종속 제거 (출제범위 외) |
| 5NF | 제5정규형 | 4NF + 조인 종속 제거 (출제범위 외) |

### 정규화와 성능
- 정규화를 하면 중복이 줄어들어 데이터 무결성은 향상
- 조인이 늘어나 조회 성능이 저하될 수 있음 → 반정규화(비정규화)로 성능 개선 가능

## 2. 관계형 데이터베이스 개요

### 데이터베이스 개념
- 데이터를 효율적으로 저장하고 관리하기 위한 데이터 집합체
- DBMS: 데이터베이스를 관리하는 소프트웨어

### 관계형 데이터베이스의 구성 요소
- **계정(User)**: 데이터의 접근 제한을 위해 업무별/시스템별로 존재 (모든 테이블이 모든 유저에게 조회되게 할 수는 없으므로)
- **테이블(Table)**: DBMS의 데이터베이스 안에 데이터가 저장되는 형식
- **스키마(Schema)**: 테이블이 어떠한 구성으로 이루어져 있는지, 즉 테이블의 기본적인 구조 정의

### 테이블(Table)
- 행과 열의 2차원 구조를 가진 데이터 저장 객체
- 관계형 데이터베이스의 기본 단위
- 릴레이션(Relation)이 곧 테이블
- **컬럼/열**: 테이블에서 세로 방향으로 이루어진 개별 속성 (더 이상 나눌 수 없는 특성, 필드(Field)라고도 함)
- **로우/행**: 테이블에서 가로 방향으로 이루어진 연결된 데이터 (레코드(Record)나 튜플(Tuple)이라고도 함)

### 테이블의 특징
- 하나의 테이블은 반드시 하나의 유저(계정)가 소유해야 한다.
- 테이블 간 관계: 1:1, 1:N, N:N
- 테이블명은 중복될 수 없으나, 소유자가 다르다면 같은 이름으로 생성될 수 있다.
- 같은 계정으로 동일한 이름을 가진 객체 생성 불가능
- 테이블은 행 단위로 데이터가 입력·삭제되며 수정은 값의 단위로 가능

## 3. SQL(Structured Query Language)

- 관계형 데이터베이스에서 데이터 정의, 조작, 제어를 위해 사용하는 언어
- SQL문법은 대·소문자 구분 X
- **종류**: 데이터 조작어(DML), 데이터 정의어(DDL), 데이터 제어어(DCL), 트랜잭션 제어어(TCL)

### SQL 실행단계
1. **파싱(Parsing)**: 문법 확인 및 구문 분석, 파싱 끝나면 Library Cache에 저장
   - Library Cache: 이전에 실행된 SQL 문에 대한 정보를 저장하는 공간
2. **실행(Execution)**: 옵티마이저(Optimizer)가 생성한 최적의 실행 계획에 따라 SQL문 실행
3. **인출(Fetch)**: 실행 결과를 데이터베이스에서 사용자에게 전송하는 과정

## 4. 관계형 데이터베이스 특징

- 데이터의 분류, 정렬, 탐색 속도가 빠르다.
- 신뢰성이 높고, 데이터의 무결성을 보장한다.
- 기존의 작성된 스키마를 수정하기 어렵다.
- 데이터베이스의 부하를 분석하는 것이 어렵다.

---

## 5. 데이터 무결성(Integrity)

- 데이터의 정확성과 일관성을 유지하고, 데이터에 결손과 부정함이 없음을 보증하는 것
- 데이터베이스에 저장된 값과 그것이 표현하는 현실의 비즈니스 모델의 값이 일치하는 정확성 의미
- **다양한 제약조건(기본키, 외래키, NOT NULL 제약, UNIQUE 제약 등)을 통해 데이터의 무결성이 유지됨**

### 데이터 무결성 종류
| 종류 | 설명 |
|------|------|
| 개체 무결성 | 테이블의 기본키를 구성하는 컬럼(속성)은 NULL값·중복값 불가 |
| 참조 무결성 | 외래키 값은 NULL이거나 참조 테이블에 실제 존재하는 값이어야 함 |
| 도메인 무결성 | 주어진 속성 값이 정의된 도메인에 속한 값이어야 함 |
| NULL 무결성 | 특정 속성에 대해 NULL을 허용하지 않음 |
| 고유 무결성 | 특정 속성에 대해 값이 중복되지 않음 |
| 키 무결성 | 하나의 관계에는 적어도 하나의 키가 존재해야 함 |

## 6. Relational Model Constraints (4대 제약 조건)

### ① 도메인 제약 (Domain Constraints)
- 속성(Attribute)에 대한 제약
- 속성 값은 원자성(Atomicity)을 가지며 도메인에서 정의된 값이어야 함
- **Composite Attribute와 Multivalued Attribute는 허용 X**
  - 사실 관계형 데이터베이스 테이블로 왔을 때는 이미 원자값을 갖는 형태로만 있어야 함
- NULL값은 허용됨 (NOT NULL이 아닌 속성이라면)

### ② 키 제약 (Key Constraints)
- 릴레이션(Relation)에 대한 제약 / 테이블에 대한 제약
- 테이블은 키(PK)를 가져야 한다.
- 릴레이션의 모든 튜플은 서로 식별 가능해야 함

### ③ 개체 무결성 제약 (Entity Integrity Constraints)
- 기본키(Primary Key)에 대한 제약
- 테이블이 가진 키는 자고로 이래야 한다는 제약
- **PK는 UNIQUE하면서 NOT NULL이어야 한다.**

### ④ 참조 무결성 제약 (Referential Integrity Constraints)
- 외래키(Foreign Key)에 대한 제약
- 릴레이션 R1이 릴레이션 R2를 참조하는 경우, R1의 FK는:
  1. NULL이거나
  2. NULL이 아닌 경우 R2에 실제로 존재하는 값으로 구성되어야 함
- FK는 자기 자신이 속한 릴레이션을 참조할 수 있다. (ex. 멘토)
- FK의 필드명은 바꿀 수 있음

> ※ 3대 제약 조건이라 하는 경우엔 키와 개체 무결성 제약을 합쳐서 말함

## 7. 트랜잭션(Transaction)

### 트랜잭션 개념
- 데이터베이스의 논리적 연산단위
- 분할할 수 없는 최소의 단위
- 전부 적용하거나 전부 취소해야 함 (ALL OR NOTHING)

### 트랜잭션의 특징 (ACID)
| 특징 | 설명 |
|------|------|
| 원자성(Atomicity) | 트랜잭션에서 정의된 연산들은 모두 성공적으로 실행되던가 아니면 전혀 실행되지 않은 상태로 남아 있어야 함 |
| 일관성(Consistency) | 트랜잭션이 실행되기 전의 데이터베이스 내용이 잘못되어 있지 않다면 트랜잭션이 실행된 이후에도 잘못되면 안 됨 |
| 고립성(Isolation) | 트랜잭션이 실행되는 도중에 다른 트랜잭션의 영향을 받아 잘못된 결과를 만들어서는 안 됨 |
| 지속성(Durability) | 트랜잭션이 성공적으로 수행되면 그 트랜잭션이 갱신한 데이터베이스의 내용은 영구적으로 저장됨 |

## 8. 상호 배타적 관계 (Exclusive Relationship)

- 하나의 엔터티가 두 개 이상의 다른 엔터티와 관계를 맺을 때, **동시에 두 관계 모두 성립할 수 없는 관계**
- 즉, 어느 한 쪽과 관계가 성립하면 나머지 관계는 성립 불가
- ex) 청구 엔터티는 자동차보험청구 또는 건강보험청구 중 하나와만 관계를 가짐

### 표기법
- ERD에서 호 모양의 아크(Arc)로 표현
- 배타적 관계로 묶인 관계선들이 하나의 아크 안에 포함

### 사용 시 주의
- 상호 배타적 관계는 NULL 허용이 많아지므로 데이터 품질 관리에 주의
- 슈퍼타입-서브타입(Supertype-Subtype) 구조로 모델링하면 상호 배타적 관계를 명확히 표현 가능

## 9. NULL 속성의 이해

- NULL은 아직 정의되지 않은 값 또는 해당 없는 값
- NULL은 '0'이나 공백('')과 다름
- **NULL값과의 수치연산은 NULL값 리턴**
- **NULL값과의 비교연산은 알 수 없음(unknown)을 반환**
  - 따라서 비교연산자 '=', '>', '<' 사용 시 WHERE 절의 조건이 알 수 없음(unknown)이 되어 데이터를 얻지 못함
  - **NULL 조회 시 반드시 IS NULL / IS NOT NULL을 사용**
  - 결괏값을 NULL이 아닌 다른 값으로 얻고자 할 때 NVL/ISNULL 함수를 사용
- 집계함수에서 NULL은 0이 아니라 계산에서 제외됨
  - COUNT(*): NULL 값 포함 전체 행의 개수
  - COUNT(컬럼): NULL을 제외한 행의 개수
  - 컬럼이 PK라면 NULL 값 허용 X → 항상 COUNT(*) = COUNT(컬럼)
  - 전체 행 개수에 대한 평균: `SUM(컬럼) / COUNT(*)` 또는 `AVG(NVL(컬럼, 0))`
