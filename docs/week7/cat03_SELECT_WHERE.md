## 1. SQL 문장들의 종류

| 명령어 종류 | 명령어 | 설명 |
|-------------|--------|------|
| DML (데이터 조작어) | SELECT | 데이터를 조회·검색하기 위한 명령어 (RETRIEVE라고도 함) |
| DML | INSERT, UPDATE, DELETE | 데이터에 변형을 가하는 명령어 |
| DDL (데이터 정의어) | CREATE, ALTER, DROP, RENAME | 테이블 같은 데이터 구조를 정의하는 명령어 |
| DCL (데이터 제어어) | GRANT, REVOKE | 데이터베이스에 접근하고 객체들을 사용하도록 권한을 주고 회수하는 명령어 |
| TCL (트랜잭션 제어어) | COMMIT, ROLLBACK | DML에 의해 조작된 결과를 트랜잭션 별로 제어하는 명령어 |

- **추가**: DDL: TRUNCATE (오토커밋), DML: MERGE, TCL: SAVEPOINT, DQL: SELECT
- **※ DML**: 사용자가 COMMIT 해야 함 → ROLLBACK 가능
- **※ DDL**: AUTO COMMIT → ROLLBACK 불가능

## 2. SELECT 문의 구조

```sql
SELECT * | 컬럼명 | 표현식
FROM   테이블명/뷰명
WHERE  조회 조건
GROUP BY 그룹화 기준 컬럼명
HAVING 그룹핑 필터링 조건
ORDER BY 정렬 기준 컬럼명
```

- 6개의 절로 구성
- 각 절의 순서대로 작성해야 한다. (GROUP BY와 HAVING의 순서는 서로 바꿀 수 있으나 보통 사용 X)
- **SELECT 문의 내부 파싱(문법적 해석) 순서는 작성 순서와 다르다.**

### SQL 논리적 실행 순서
```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
```

1. DB는 우선 FROM 절로 가서 어떤 테이블을 가져와야 하는지 파악
2. WHERE 절로 가서 조건에 맞는 데이터만 필터링
3. 필터링 후에 GROUP BY 절로 가서 필터링한 데이터를 그룹화
4. HAVING 절을 보고 그 그룹화된 결과에 대해 다시 필터링
5. SELECT 절에서 필요한 컬럼만 추출
6. ORDER BY 절을 보고 데이터를 정렬

## 3. SELECT 절

- SELECT 문장을 사용하여 불러올 컬럼명, 연산 결과를 작성하는 절
- `*`: 테이블 내 모든 컬럼 조회
- `SELECT 열1, 열2, ... FROM 테이블명;` 으로 여러 컬럼 조회 가능
- **표현식**: 기존 컬럼명을 그대로 적는 것이 아니라 연산식, 기존 컬럼의 함수 변형식

### AS (별칭, Alias)
- SQL에서 별칭(Alias)을 만들 때 사용하는 키워드 (생략 가능하다)
- 별칭을 통해 출력할 컬럼이나 테이블에 임시로 이름을 부여할 수 있다.
- 별칭은 결과에만 적용되며, 실제 데이터베이스 테이블에는 영향 X
- **SELECT 문보다 늦게 사용되는 ORDER BY절에서만 컬럼 별칭 사용 가능** (HAVING이나 WHERE 절에서 사용 시 에러 발생)
- **※ 오라클에서 테이블 별칭을 명시할 때 AS를 사용할 수 없다!**
- 다음의 경우 큰따옴표(" ")를 사용한다. (역따옴표도 사용 가능)
  - 공백 포함
  - 특수문자 포함 ( _, $, #는 제외 )
  - 별칭 그대로 전달하고자 할 때

### SELECT [ALL/DISTINCT]
- **ALL**: 디폴트 옵션이라 별도로 표시하지 않아도 됨. 중복된 데이터가 있어도 모두 출력
- **DISTINCT**: 중복된 데이터가 있는 경우, 1건으로 처리해서 출력

## 4. FROM 절

- 데이터를 불러올 테이블명이나 뷰명 전달
- 여러 테이블 전달 가능 (콤마로 구분)
- **여러 테이블 사이에 JOIN 조건이 존재하지 않다면, SQL은 두 테이블의 모든 가능한 조합을 생성한다. (이를 Cartesian Product라고 함)**
- 테이블도 별칭 선언 가능 (ORACLE은 AS 사용 불가, SQL Server는 사용/생략 가능)
- **테이블에 별칭을 사용 시, 해당 테이블을 참조할 때 반드시 별칭을 사용해야만 한다.**
- **ORACLE에서는 FROM 절 생략 불가** (Oracle 23c 버전부터는 가능)
  - 의미상 테이블이 필요 없다면 DUAL 테이블을 선언한다.
- SQL Server에서는 FROM 절이 필요 없다면 생략 가능

### VIEW(뷰)
- 테이블과 동일하게 데이터를 조회할 수 있는 객체지만, 테이블처럼 실제 데이터가 저장된 것이 아닌 SELECT 문 결과에 이름을 붙여 그 이름만으로도 조회가 가능하도록 만든 기능

### DUAL 테이블의 특성
- 23c이전 버전의 오라클에서는 SELECT 문 작성시 FROM 절 필수
- 데이터를 가져올 테이블이 필요 없는 경우 DUAL 테이블을 사용 (Sybase나 SQL Server의 경우 SELECT 절만으로도 수행 가능)
- 사용자 SYS가 소유하며 모든 사용자가 액세스 가능한 테이블 (SYS: DB의 관리자 계정)
- SELECT ~ FROM ~ 의 형식을 갖추기 위한 일종의 DUMMY 테이블
- DUMMY라는 문자열 유형의 컬럼에 'X'라는 값 1건 포함

## 5. SQL 문 작성 시 주의사항

- 문자 상수나 날짜 상수 표현 시 홑따옴표 사용하기
- ORACLE은 문자 상수의 경우 대소문자를 구분한다.
- MSSQL은 기본적으로 문자 상수의 대소문자를 구분 X
- MySQL은 비교나 검색을 수행할 때 기본적으로 대소문자 구분 없이 비교 및 검색이 가능하다.

## 6. WHERE 절

### 특징
- 테이블의 데이터 중 원하는 조건에 맞는 데이터만 조회하고 싶을 때 사용 (엑셀의 필터기능 같은 것)
- 조건을 설정하여 원하는 데이터만 검색하기 위해 사용하는 절
- 여러 조건 동시 전달도 가능 (AND나 OR로 조건 연결)
- **NULL은 '='로 조회가 불가능, IS NULL / IS NOT NULL을 사용**
- 조건 전달 시 비교 대상끼리 데이터 타입이 일치하는 것이 좋음
- **집계 함수 사용 불가**

### WHERE 절 구문
```sql
SELECT [DISTINCT/ALL] 컬럼명 [ALIAS명]
FROM 테이블명
WHERE 조건식;
```

### 연산자의 종류

**비교 연산자:**
| 연산자 | 의미 |
|--------|------|
| = | 같다 |
| > | 보다 크다 |
| >= | 보다 크거나 같다 |
| < | 보다 작다 |
| <= | 보다 작거나 같다 |

**SQL 연산자:**
| 연산자 | 의미 |
|--------|------|
| BETWEEN a AND b | a와 b값 사이 (a, b 포함) |
| IN (list) | 리스트에 있는 값 |
| LIKE '비교문자열' | 비교문자열과 형태 일치 |
| IS NULL | NULL 값인 경우 |

**논리 연산자:**
| 연산자 | 의미 |
|--------|------|
| AND | 앞·뒤 조건 모두 만족 |
| OR | 앞·뒤 조건 중 하나라도 참 |
| NOT | 뒤에 오는 조건에 반대되는 결과 |

**부정 비교 연산자:**
| 연산자 | 의미 |
|--------|------|
| != | 같지 않다 |
| ^= | 같지 않다 |
| <> | 같지 않다 (ISO표준) |
| NOT 칼럼명 = | ~와 같지 않다 |
| NOT 칼럼명 > | ~보다 크지 않다 |

**부정 SQL 연산자:**
| 연산자 | 의미 |
|--------|------|
| NOT BETWEEN a AND b | a와 b값 사이X (a, b 포함X) |
| NOT IN (list) | 리스트에 없는 값 |
| IS NOT NULL | NULL 값을 가지지 않음 |

### 연산자 우선순위
| 우선순위 | 연산자 |
|----------|--------|
| 1 | 괄호 |
| 2 | 부정 연산자 (NOT 연산자) |
| 3 | 비교 연산자, SQL 연산자 |
| 4 | AND |
| 5 | OR |

## 7. WHERE 세부 조건

### WHERE와 논리 연산자
- AND는 OR보다 우선순위가 높아 AND 연산자가 OR 연산자보다 우선적으로 실행된다.
- 괄호를 분명히 사용하자.

### WHERE와 IN
- 특정 컬럼의 값이 지정된 목록 중에서 일치하는 값이 있는지 확인
- OR 사용해 표현 가능하지만, IN을 사용하면 쿼리가 훨씬 간결해짐
- **IN은 NULL값을 무시**
- NOT IN은 IN의 반대 연산자로, 목록에 없는 값을 필터링

### WHERE와 BETWEEN A AND B
- A 보다 크거나 같고 B 보다 작거나 같은 조건을 만족 (**반드시 A < B**)
- A와 B에는 범위로 묶을 상수값 전달 (숫자, 문자, 날짜 모두 가능)

### WHERE와 LIKE (LIKE 연산자는 대소문자 구분함)
- LIKE는 특정 패턴과 일치하는 데이터를 조회할 때 사용
- 주로 와일드카드와 함께 사용되어 부분적으로 일치하는 문자열을 찾음

**와일드카드:**
| 와일드카드 | 의미 |
|------------|------|
| % | 0개 이상의 문자를 대체 (해당 위치에 몇 글자든 올 수 있음) |
| _ | 딱 1개의 문자만을 대체 (해당 위치에 반드시 한 글자만 올 수 있음) |

**예시:**
```sql
WHERE 이름 LIKE 'S%'     -- 이름이 S로 시작
WHERE 이름 LIKE '%S%'    -- 이름이 S를 포함 (시작하거나, 끝나는 데이터도 포함)
WHERE 이름 LIKE '%S'     -- 이름이 S로 끝남
WHERE 이름 LIKE '__S'    -- 이름이 3글자며 S로 끝남 (앞에 _ 두 개)
WHERE 이름 LIKE '_S%'    -- 이름의 두 번째 글자가 S
WHERE 이름 LIKE '__S__'  -- 이름이 5글자며 가운데 글자가 S
```

### WHERE와 IS NULL
- **NULL값과의 수치연산은 NULL값 리턴**
- **NULL값과의 비교연산은 UNKNOWN을 리턴** (TRUE도 FALSE도 아닌 제3의 값)
- 따라서 비교연산자 '=', '>', '<' 사용 시 WHERE 절의 조건이 UNKNOWN이 되어 데이터를 얻지 못함 (WHERE는 TRUE인 행만 통과)
- 어떤 값과 비교할 수도 없으며, 특정 값보다 크다·적다고 표현 불가

```sql
SELECT PLAYER_NAME, TEAM_NAME
FROM PLAYER
WHERE POSITION IS NULL;  -- 포지션이 없는 선수 조회
```

## 8. ORDER BY 절

### ORDER BY 절 개념
- 원칙적으로 관계형 데이터베이스 환경에서는 ORDER BY 절을 명시해야 데이터 정렬이 수행된다.
- ORDER BY 뒤에 정렬의 기준이 되는 컬럼을 명시하면 된다. (여러 컬럼이 기준 시, 가장 왼쪽 컬럼부터 우선순위가 적용됨)
- 정렬 순서: **ASC(오름차순), DESC(내림차순)** / 기본 값: ASC
- **유일하게 SELECT 절에 정의한 컬럼 별칭 사용 가능**
- 숫자뿐만 아니라 문자, 날짜 타입도 정렬 가능
- 날짜의 가장 작은 값은 가장 과거인 날짜
- 문자 데이터의 경우 첫 번째 문자가 같은 값이면, 두 번째 값을 기준으로 정렬한다.
- **ORACLE에서 NULL은 최댓값, SQL Server에서는 최솟값**
- ORACLE은 ORDER BY 절에 NULL LAST | NULL FIRST 를 명시해 NULL의 정렬 순서 변경이 가능
- **GROUP BY로 그룹화를 했을 시 ORDER BY에 올 수 있는 컬럼은 SELECT 절에 있는 컬럼만 가능하다.**

### ORDER BY 구문
```sql
SELECT 컬럼명
FROM 테이블명
WHERE 조건식
GROUP BY 그룹핑컬럼명
HAVING 그룹 조건식
ORDER BY 정렬컬럼명 [ASC | DESC]
```

### 다중 컬럼 정렬
- 1차 정렬의 기준이 된 컬럼을 기준으로 동일한 값을 가지는 행들의 경우 두 번째 컬럼을 기준으로 정렬(2차 정렬)이 되는데, 이를 통해 세부적인 정렬이 가능하기 때문
- 즉, 1차 정렬한 값이 같은 행들에 한해서 2차 정렬이 일어난다는 것
- 따라서 동일한 값이 나올 수 없는 데이터는 굳이 2차 정렬을 할 필요가 없다.
