## 1. 연구 배경 및 목적

### 1.1 문제 정의

SQLD(SQL Developer) 자격증은 국가공인 데이터베이스 자격증으로, 데이터 직군 취업 준비생과 재직자에게 널리 요구된다. 그러나 기존 학습 방식에는 다음과 같은 문제가 있다.

- **취약점 파악 어려움:** 어느 카테고리가 약한지 스스로 진단하기 어렵다 (인터뷰 4/5명 응답)
- **개념→문제 적용 갭:** 개념을 알아도 실전 문제에 적용하지 못한다 (4/5명)
- **오답 복습 비효율:** 틀린 문제를 체계적으로 재복습할 방법이 없다 (3/5명)
- **해설 불충분:** 왜 틀렸는지 이해하기 어렵다 (3/5명)

이 프로젝트는 위 페인포인트를 해결하는 **LangGraph 기반 적응형 AI 튜터**를 설계·구현하고, 실사용자 베타 테스트를 통해 효과를 검증하는 것을 목표로 한다.

### 1.2 연구 질문

1. AI 튜터가 사용자의 약점 카테고리를 정확히 진단하고 맞춤 문제를 제공할 수 있는가?
2. 반복 학습을 통해 약점 카테고리 정답률이 향상되는가?
3. LLM 기반 개념 설명이 사용자가 체감할 수 있는 수준의 품질을 갖추는가?

## 2. 시스템 설계 및 구현

### 2.1 기술 스택

| 레이어 | 기술 | 선택 이유 |
|--------|------|-----------|
| AI Agent | LangGraph (Python) | 상태 기반 멀티노드 대화 흐름 제어 |
| LLM | Claude Sonnet 4.6 (Anthropic) | 한국어 SQLD 문맥 이해 품질 |
| Backend | FastAPI + SSE | 토큰 단위 스트리밍 응답 |
| Frontend | Next.js 14 (App Router) | SSE 수신 및 실시간 UI 렌더링 |
| DB / Auth | Supabase (PostgreSQL) | 인증 + 학습 데이터 영속성 |
| Memory | LangGraph PostgresSaver | 대화 체크포인트 영속 저장 |
| RAG | Chroma DB + Gemini Embedding | 카테고리별 개념 검색 |
| Observability | LangSmith | LLM 트레이스 모니터링 |

### 2.2 LangGraph 에이전트 구조

시스템은 다음 7개 노드로 구성된다.

```
사용자 입력
    ↓
intent_classifier  → 의도 분류 (drill / review / explain / diagnose / sql / follow_up)
    ↓
[분기]
├── chatbot_node    → 일반 대화 + 도구 호출
├── drill_node      → 문제 출제 + 채점
├── review_node     → 오답 복습
├── explain_node    → RAG 개념 설명
├── diagnose_node   → 약점 분석 리포트
└── sql_node        → SQL 실행 샌드박스
    ↓
state_updater       → 정답률·streak·약점 업데이트
    ↓
adaptive_difficulty_router → 다음 난이도·카테고리 결정
```

### 2.3 적응형 학습 알고리즘

- **진단 8문제:** 목표 점수(60/70/80/90점)별 가중치로 난이도 자동 선택
- **진단 후:** 카테고리별 정답률 기반 자동 난이도 조정 (70%↑→상, 40~70%→중, 40%↓→하)
- **카테고리 전환:** 동일 카테고리 3연속 정답 시 다음 약점 카테고리로 자동 전환
- **오답 즉시 설명:** 오답 발생 시 RAG 기반 개념 설명 자동 트리거

### 2.4 문제 은행

- 총 220문제 (11개 카테고리 × 20문제)
- 2024년 SQLD 개정 기준 (절차형 SQL 삭제, TOP N/PIVOT/정규표현식 추가)
- 난이도 분류: 하(A유형) / 중(C·D유형) / 상(B·E유형)

### 4.4 A/B 테스트 결과 (15주차)

#### 실험 설계

- **연구 질문:** 오답 후 개념 설명 자동 제공 vs 학습자가 직접 요청하는 방식 중 어느 쪽이 학습에 더 효과적인가?
- **설계 방식:** 동일 피험자 내 순차 비교 (Within-Subject Sequential A/B)
- **A 기간 (자동설명):** 2026-07-24 ~ 07-27 (4일), `AUTO_EXPLAIN=true` (기본값)
- **B 기간 (직접질문):** 2026-07-28 ~ 07-31 (4일), `AUTO_EXPLAIN=false` (Render 환경변수)
- **전환 방법:** 코드 재배포 없이 Render 대시보드에서 환경변수만 변경
- **사후 평가:** 구글폼 18문항 (2026-07-31 ~ 08-01, 3명 전원 응답)

#### 정량 분석

| 기간 | 풀이수 | 정답률 |
|------|--------|--------|
| A — 자동설명 (24~27일) | 241문제 | 88.4% |
| B — 직접질문 (28~31일) | 50문제 | 74.0% |

> **주의:** 전체 집계는 특정 사용자 쏠림 현상으로 인한 착시임.

**테스터별 기간 비교:**

| 테스터 | A 풀이수 | A 정답률 | B 풀이수 | B 정답률 | 변화 |
|--------|----------|----------|----------|----------|------|
| 테스터 B | 195 | 99.5% | 24 | 100.0% | +0.5% |
| 테스터 A | 33 | 48.5% | 15 | 53.3% | +4.8% |
| 테스터 C | 8 | 25.0% | 9 | 55.6% | +30.6% |

개인별로 보면 B기간(직접질문)에서 정답률이 같거나 높아짐. 전체 평균 A > B는 테스터 α가 A기간에 195문제를 99.5%로 풀어 전체의 81%를 차지한 결과.

B기간 풀이수 급감(33→4→5→8)은 테스터 γ의 난이도 '상' 재고 버그로 이틀간 문제를 거의 못 푼 것이 원인.

#### 정성 분석

**A/B 선호도:**

| | 테스터 A | 테스터 B | 테스터 C |
|---|---|---|---|
| 자동 설명 경험 | 귀찮았다 | 귀찮았다 | 유용했다 |
| 직접 질문 경험 | 더 집중해서 읽게 됐다 | 비슷했다 | 더 집중해서 읽게 됐다 |
| 최종 선호 | **직접 질문** | **직접 질문** | 자동 |

2:1로 직접 질문 우세. 테스터 C의 자동 선호는 되묻기 경로 불안정으로 인한 안전상 선택으로 판단 — 버그 없는 환경이었다면 직접 질문 선호가 3:0이었을 가능성 높음.

**페인포인트 해소 점수 (5점 만점):**

| | 테스터 A | 테스터 B | 테스터 C | 평균 |
|---|---|---|---|---|
| 취약점 파악 | 5 | 3 | 1 | 3.0 |
| 개념→문제 갭 | 5 | 4 | 3 | 4.0 |
| 오답 복습 | 4 | 4 | 1 | 3.0 |
| AI 설명 이해 | 5 | 4 | 3 | 4.0 |
| **NPS (추천 의향)** | **10** | **7** | **3** | **6.7** |

테스터 C 전반 저점수의 주 원인: 난이도 '상' 재고 버그로 7월 29~30일 이틀간 문제를 한 개도 못 푼 것 — 기능 문제 아님.

**예상 못 한 긍정 요소:**
- 카테고리별 정답률 시각화 — "게임처럼 채우는 게 재밌다" (테스터 A)
- SQL 실행기 — "설명 여섯 번 듣는 것보다 눈으로 보는 게 나았다" (테스터 C)
- 정답 시 자동 해설 — "맞혔어도 나머지 선택지 오답 이유까지 나와서 그냥 안 넘기게 됐다" (테스터 C)

#### 결론

1. 직접 질문 방식이 학습 집중도를 높이는 경향이 있음 (2/3 테스터 공통 인식)
2. 전체 집계 A > B는 통계 착시 — 개인별 비교 시 B 동등하거나 우세
3. B기간 풀이수 급감은 방식의 문제가 아닌 시스템 버그 원인
4. 표본(3명, 50문제)이 너무 작아 통계적 유의성은 없음 — 방향성 참고용

## 8. 사업성 분석

### 8.1 시장 분석

SQLD 자격증 응시자는 2022년 32,474명에서 2025년 62,664명으로 3년간 연평균 24.5% 성장. 2025년 합격률이 57.3% → 41.7%로 급락하며 단순 암기 방식의 한계가 드러났고, 이는 구조화된 학습 도구에 대한 수요 증가 요인으로 작용한다.

| 구분 | 규모 | 산출 근거 |
|------|------|-----------|
| TAM (전체 시장) | 연 44~81억원 | 응시자 62,664명 × 1인당 지출 7~13만원 |
| SAM (접근 가능 시장) | 연 7.5억원 | TAM의 20% × 월 5,000원 × 12개월 |
| SOM (목표 시장) | 연 5,850만원 | SAM의 10%(1,250명) × 월 3,900원 × 12개월 |

*SAM 20% 이용률, SOM 10% 점유율은 보수적 업계 평균 기반 추산값. SAM은 시장 규모 비교용 5,000원 기준, SOM은 실제 확정 가격 3,900원 기준으로 산출.*

### 8.2 경쟁 포지셔닝

기존 도구는 두 유형으로 나뉜다. **SQLD 특화지만 정적인 도구**(기출집, 인강, 요약집)와 **스마트하지만 비특화된 도구**(ChatGPT, Gemini). sqld-tutor는 두 유형의 교차점에 위치한 유일한 서비스다.

핵심 차별점:
- 기출집 대비: 오답 자동 기록 + 재출제 + 약점 카테고리 진단
- 인강 대비: 내 약점만 집중 학습, 비용 1/10 수준
- 범용 AI 대비: 220개 검증된 SQLD 문제 + 결정론적 채점 (오채점 없음)

> sqld-tutor는 GPT의 대체재가 아니라, 자기주도 학습이 어려운 수험생을 위한 구조화된 학습 코치다.

### 8.3 가격 정책

| 플랜 | 내용 | 가격 |
|------|------|------|
| 무료 | 진단 8문제 + 하루 5문제 + 기본 채점 | 0원 |
| 유료 | 무제한 문제 + 오답 복습 + 약점 분석 + 개념 설명 | 월 3,900원 |

**LTV 추산:** 월 3,900원 × 평균 이용 2개월 × 불합격 재수험 30% = 약 10,140원  
**1인당 원가:** LLM $1.3 ≈ 1,900원/월 → **마진율 약 51%**

### 8.4 Phase 2 사업계획 (참고용)

- **목표:** 12개월 내 유료 사용자 500명
- **월 매출 목표:** 500명 × 3,900원 = 195만원
- **성장 전략:** 오픈카톡 SQLD 스터디방 · 블라인드 · 에브리타임 커뮤니티 중심 무비용 마케팅
- **제품 로드맵:** 결제 연동 → 문제 350개 확장 → SQLP·ADsP 확장
