## q001 | 데이터 모델링 기초 | A유형 | 난이도: 하

**문제:** 다음 중 데이터 모델링의 특징에 대한 설명으로 옳은 것은?

- ① 현실 세계의 모든 세부 사항을 그대로 저장하는 것이 데이터 모델링의 핵심이다.
- ② 데이터 모델링은 업무에서 필요한 데이터 구조를 일정한 표기법으로 표현하는 과정이다.
- ③ 데이터 모델링은 물리 모델 단계에서만 수행되며 개념 모델에는 적용되지 않는다.
- ④ 데이터 모델링은 데이터 중복을 의도적으로 늘려 조회 속도를 높이는 활동만을 의미한다.

**정답:** 2번

**힌트:** 데이터 모델링은 현실 세계를 그대로 복사하는 것이 아니라 필요한 구조로 표현하는 과정이다.

**해설:** 데이터 모델링은 현실 세계의 업무를 분석해 필요한 데이터와 관계를 추상화하고, 이를 일정한 표기법으로 표현하는 과정이다. 현실의 모든 세부사항을 그대로 담는 것이 아니며, 개념/논리/물리 모델 전 단계에서 수행될 수 있다.

## q002 | 데이터 모델링 기초 | A유형 | 난이도: 하

- ① 추상화는 모든 예외 상황을 상세하게 나열하는 것이다.
- ② 단순화는 실제 업무 규칙을 제거하여 의미를 없애는 것이다.
- ③ 명확화는 누구나 동일하게 해석할 수 있도록 모델을 분명하게 표현하는 것이다.

## q010 | 데이터 모델링 기초 | E유형 | 난이도: 상

**[참고 자료]**
```
다음 ERD를 참고하시오.

[학생] ──< 수강 >── [과목]
- 학생(학생번호 PK, 학생명)
- 과목(과목코드 PK, 과목명)
- 수강(학생번호 PK/FK, 과목코드 PK/FK, 수강신청일자)

업무규칙:
1) 한 학생은 여러 과목을 수강할 수 있다.
2) 한 과목은 여러 학생이 수강할 수 있다.
3) 동일 학생이 동일 과목을 같은 학기에 중복 수강신청하는 것은 허용하지 않는다.
```

**문제:** 다음 중 위 ERD와 업무규칙에 대한 설명으로 옳은 것은?

- ② 수강 엔터티의 기본키는 수강신청일자만으로 정의하는 것이 가장 적절하다.

- ④ 학생과 과목의 관계는 1:1 관계이므로 수강 엔터티는 불필요하다.

**정답:** 1번

**힌트:** 학생과 과목은 서로 여러 건씩 연결될 수 있다.

**해설:** 학생과 과목의 관계는 M:N 관계이므로 이를 해소하기 위해 교차 엔터티인 수강을 두는 것이 적절하다. 수강 엔터티에서 학생번호와 과목코드는 각각 부모 엔터티를 참조하는 외래키이면서, 조합에 따라 식별자로 활용될 수 있다.

## q011 | 데이터 모델과 SQL | A유형 | 난이도: 하

**문제:** 다음 중 제2정규형(2NF)에 대한 설명으로 옳은 것은?

- ① 제1정규형을 만족하면서 기본키가 아닌 모든 속성이 기본키 전체에 완전 함수 종속인 상태를 말한다.
- ② 모든 결정자가 후보키인 상태를 말하며 BCNF와 동일하다.
- ③ 다치 종속을 제거한 상태를 말하며 제4정규형과 동일한 의미로 사용된다.
- ④ 반드시 모든 속성이 단일 속성 기본키에만 종속되도록 만드는 것을 의미한다.

**정답:** 1번

**힌트:** 부분 함수 종속 제거가 어느 정규형의 핵심인지 떠올려 보자.

**해설:** 정답은 1번이다. 2NF는 1NF를 만족하고, 기본키가 복합키일 때 기본키의 일부에만 종속되는 부분 함수 종속을 제거한 상태를 말한다. 2번은 BCNF의 설명에 가깝고 2NF와는 다르다. 3번은 제4정규형 관련 설명으로 2NF와 무관하다. 4번도 틀렸다. 2NF는 단일 속성 기본키만 허용하는 개념이 아니라, 복합키 환경에서 부분 종속을 제거하는 것이 핵심이다.
